# Windows 预览文件占用修复

日期：2026-09-29。

## 已确认的问题

正式任务 `555530657cd44f2483e56d5c25ab737c` 在 N256 / Re5468 的第 651600 步报告后，因 `preview.tmp` 替换 `preview.npz` 返回 `PermissionError: [WinError 5]` 而退出。该异常不是求解器的数值保护停止，不能作为高 Re 搜索的未通过端。

日志只能确定文件替换被拒绝，不能确认当时的具体占用进程。读取预览的看板和同步客户端均可能造成占用，本次未对实际占用来源作已证实断言。

## 修复范围

- `dashboard/worker.py`：仅对预览替换的 PermissionError 作最多 4 次尝试，总等待 0.1 秒。预览生成或发布的 OSError 只导致这次预览跳过，不终止计算；保留最后完整预览，并尽力清理本次临时文件。
- 预览失败及恢复写入工作日志，重复失败日志限制频率；诊断记录增加预览步数、累计跳过次数和当前警告，最终摘要包含 `preview_status`。
- `dashboard/analysis.py`：预览先读入最多 16 MB 的内存快照，关闭 Windows 文件句柄后再解压；解压总量也受 16 MB 限制。临时不可读或损坏的预览产生警告，不丢弃已有标量曲线。
- `dashboard/app.py`：活动任务有预览写入警告时显示预览暂缓状态。成功刷新后恢复正常显示。

这些容错仅用于可丢弃的预览。正式结果、诊断记录、数据库及未知程序错误仍严格报错。没有更改碰撞、边界、残差、停止判据、精度或计算参数；没有添加从预览恢复分布函数的功能。

## 用户重新计算

1. 关闭并重新打开工作台，以加载新的预览读取与状态显示代码。无须重新安装环境。
2. 在“数据档案”中选择原失败算例，点击“复用参数”。
3. 确认 CPU/GPU 后端、N、Re、速度、步数和阈值后，手动开始新算例。

原失败记录仍为 failed，没有删除、覆盖或重排。它没有完整分布函数检查点，因此新算例从初始条件重算，不是从第 651600 步续算。本次未向正式队列加入任何任务，也没有代替用户开始重算。
